# 跨系统、跨设备路径兼容性核查与修复说明

- 核查日期：2026-11-27
- 适用项目：PhyAgentOS-Kimi-Plugin
- Core 基线：`@x-era/forge-core@0.2.2`
- 本轮状态：完成路径兼容性核查及本文档编写；本文列出的兼容性修复尚未实施。

## 1. 背景与目标

插件需要在不同用户名、安装位置、操作系统和 CPU 架构的设备上，正确定位配置、技能、模型、依赖缓存及运行文件。用户不应依赖开发者电脑的目录结构才能使用插件。

此前已经完成 Core 0.2.2 版本对齐、构建补丁路径修复及相关回归验证。这些改动解决的是依赖与构建一致性，不代表下文的跨平台路径问题已经修复。

本轮检查范围包括插件源码、生成的 MCP 载荷、构建与维护脚本、配置清单、使用文档、测试，以及当前安装的 Core 和对应补丁。本文的源码行号对应核查时版本，后续修改可能使其变化。

## 2. 核查结论

未发现插件发布源码把 `/home/gx/...`、开发者用户名或当前项目 checkout 目录写成运行时固定路径。

发现的问题主要包括：

1. Core 部分实现依赖 POSIX 目录、工具或权限语义。
2. 启动器与适配层的路径展开规则不一致。
3. Windows 反斜杠路径和相对路径的解析存在缺口。
4. 配置中的环境变量占位符不会自动展开。
5. 运行派生文件会保存当前设备的路径，不能假定复制后即可复用。
6. 使用文档包含需要替换的绝对路径，SSH 部署步骤还遗漏拆分后的运行时文件。

当前证据不足以宣称 Windows、macOS、Linux 全功能兼容。平台原生节点还需要匹配对应的操作系统和 CPU 架构，路径修复本身不能使 Linux 二进制在其他系统直接执行。

## 4. 需要修复或明确约定的问题

### 4.1 Dora 虚拟环境使用固定 POSIX 布局

位置：`node_modules/@x-era/forge-core/lib/bootstrap.js:318`、`:348`。

自动安装分支使用 `<venv>/bin/python`、`<venv>/bin/dora`，并创建指向该布局的软链接。Windows 虚拟环境通常使用 `Scripts` 目录及带 `.exe` 后缀的程序，当前分支缺少相应适配。

影响：Windows 自动初始化可能无法找到刚安装的解释器或 Dora。Core 另有用户提供本地 binary 的分支，因此不能据此认定所有安装方式都不可用。

建议：集中定义各平台的虚拟环境目录、程序名与暴露方式，同时保留显式程序路径和 PATH 查找能力。

### 4.2 启动器与适配层的波浪号展开不同

位置：`src/runtime-bootstrap.mjs:13`、`src/paths.mjs:21`；Core 的 `lib/paths.js:38`。

启动器支持 `~`、`~/`、`~\\`，适配层使用的 Core 展开函数仅处理 `~` 和 `~/`。

本机复现：输入 `KIMI_FORGE_HOME=~\\forge`，启动器展开到用户主目录，适配层却把它当作工作目录下的普通路径。

建议：启动器和适配层共享同一套路径解析契约，并覆盖两个目录分隔符。启动器应继续保持首次安装前不依赖 Core 的能力。

### 4.3 Windows 相对程序路径识别不完整

位置：`src/forge-mcp.mjs:61`–`:64`。

`resolveBin` 仅通过 `/` 或开头的 `~` 判断输入是否为路径，因此 `.\\tools\\dora.exe` 不会按 Forge home 解析。Core 启动子进程时会切换工作目录，未经规范化的相对程序路径可能因此改变含义。

已通过 Windows 路径 API 对照验证该判断分支；未进行 Windows 原生进程启动验收。

建议：区分 PATH 命令名、绝对路径、普通相对路径及盘符相对路径，路径类配置在启动子进程前按明确基准解析。UNC 路径和带空格路径也应纳入测试。

### 4.4 相对路径的解析基准不同

| 输入类型 | 当前基准 | 位置 |
| --- | --- | --- |
| 相对的 Forge/Kimi 根目录配置 | MCP 进程工作目录 | `src/paths.mjs:9`、`:21` |
| `skills.roots`、`models.root` | Forge home | `src/forge-mcp.mjs:44`–`:48` |
| 本地包、校验路径、打包输出目录 | MCP 进程工作目录 | `src/forge-mcp.mjs:244`、`:246`、`:262` |
| 显式导出目录 `out` | MCP 进程工作目录 | `src/forge-mcp.mjs:315`–`:317` |

不同用途可以采用不同基准，但必须形成稳定、可测试的约定。当前工具参数的相对路径不应被误认为相对于用户桌面工作区或配置文件所在目录。

建议：根目录配置要求绝对路径或主目录路径；配置中的资源相对路径以 Forge home 为基准；工具输入明确返回最终解析位置。改变现有规则时需要说明兼容影响。

### 4.5 配置中的环境变量占位符不展开

位置：`src/paths.mjs:32`。

本机复现确认，传入 `$HOME/models`、`${KIMI_CODE_HOME}/forge`、`%USERPROFILE%\\models` 时，这些占位符被当作普通文件名的一部分。

通过 shell 预先展开后再传入的环境变量，与直接写入 JSON 的字符串不同，不能混为一谈。

建议：明确支持的占位符语法；若不支持，应给出清晰错误，避免静默写到意外目录。不要通过 shell 执行字符串来实现展开；未定义变量也应明确报错。

### 4.6 POSIX 进程发现与目录分隔符假设

| 位置 | 当前假设 | 影响范围 |
| --- | --- | --- |
| Core `lib/runtime.js:717`、`:726` | 读取 `/proc` 及进程环境 | 缺少 procfs 时，补充发现和核验残留进程的能力下降；已有失败回退 |
| Core `lib/runtime.js:634` | 调用 PATH 中的 `ps -eo pid=,ppid=` | 不支持该接口的平台，后代进程枚举与清理覆盖可能下降 |
| Core `lib/runtime.js:401` | `nodes` 目录排除正则仅识别 `/` 边界 | 反斜杠路径可能无法匹配该排除条件 |
| Core `lib/settings.js:93`、`:123` | 按 `/` 拆分宿主路径 | Windows 反斜杠路径影响上游配置备份枚举及恢复 |

本插件实际配置存储使用 `KimiConfigStore`，不能把上游 `settings.js` 的问题直接认定为当前 `config.json` 备份故障。归档成员路径使用 POSIX 格式则属于归档规范，不应作为宿主路径缺陷修改。

建议：宿主路径使用平台路径 API；进程发现与清理采用平台分支，明确降级行为，并验证不会遗留由插件启动的进程。

### 4.7 与路径相关的执行和权限限制

Core `lib/nodes.js:192` 使用 POSIX 执行位判断文件可执行性；`lib/runtime.js:395` 在运行目录中创建软链接。Windows 的执行判断与普通用户软链接权限需要另行适配。

建议：对各平台验证真实启动能力；评估链接、复制或启动代理等方案时，同时保留归档安全边界、依赖库相对位置及节点资源布局。不得通过放开不安全链接来解决平台兼容问题。

## 5. 运行数据迁移问题

以下文件属于运行派生产物，可能包含当前设备的绝对路径：

| 产物 | 保存内容 | 代码位置 |
| --- | --- | --- |
| 物化运行副本 | runtime/bin、模型根和技能根等替换结果 | Core `lib/runtime.js:404`–`:408` |
| `runtime-lock.json` | `binaries`、`modelsRoot`、`modelEnv` | Core `lib/runtime.js:427`–`:434` |
| `runtime/state.json` | `envDir`、`dora` 等运行状态 | Core `lib/runtime.js:253`–`:262`、`:492`–`:499` |

这些路径在运行时生成，并非源码绑定开发者设备；其中 `dora` 也可能只是 PATH 命令名。

迁移设计应将用户资源与运行派生产物区分处理：

- 技能源文件、用户配置、模型及其完整性信息按迁移规则保留并核验。
- 配置中的程序、模型等设备路径需要在新设备重新确认。
- 运行副本、旧进程状态和包含旧设备路径的锁定信息应按新设备重新生成或校验，不能直接当作有效状态。
- 缓存必须核对系统、架构、版本和摘要，不得直接执行另一平台的节点。

后续实现必须保留旧数据，并在确认进程已停止后处理运行状态；本文不授权删除已有目录或状态文件。
